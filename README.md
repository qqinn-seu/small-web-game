1

双人浏览器五子棋，采用 Vite + TypeScript + Canvas 前端和 Node.js + Express + Socket.IO 服务端。完整方案见 [SchemeDesign.md](./SchemeDesign.md)，进度与验收见 [TODO.md](./TODO.md)。M1、M2、M3已人工验收，M4已实现双侧像素棋友、状态动画、短音效与界面打磨，等待用户人工验收；Render上线仍留待M5。

## 本地运行与更新

需要 Node.js 24。首次克隆后，使用 nvm 时：

```bash
nvm install
nvm use
npm ci
npm run dev
```

打开 http://localhost:5173 。Vite 将 Socket.IO 请求代理到 http://127.0.0.1:3000 。保持终端运行；停止服务按 Control+C。

从旧里程碑更新时，先停止旧服务，在项目根目录执行：

```bash
git pull --ff-only
npm ci
npm run dev
```

若Git提示有本地修改或冲突，请先保留并检查修改，不要强制覆盖。安装脚本仅批准锁定的esbuild构建工具和macOS可选文件监听fsevents；不用关闭所有脚本检查。

M4页面版本标记为`M4 v0.4.0`。升级重启会丢失旧内存房间，请新建房间验收，不能沿用此前服务进程中的对局。

生产模式本地验证：

```bash
npm run build
npm start
```

打开 http://localhost:3000 。一个Node服务同时提供静态前端与Socket.IO，监听0.0.0.0，读取PORT（缺省3000）。`PORT=4000 npm start`可变更生产端口；开发代理仍默认3000。`.env.example`仅说明变量，当前不会自动加载本地`.env`。

## 规则、身份与房间

15×15棋盘，黑棋先手，无禁手，横/竖/两斜方向连续五子及以上获胜；满盘无胜者为平局。鼠标或触摸交叉点落子，服务端确认前显示“落子中”，不会提前在本地放棋子。

首次输入昵称，服务端发放playerId与随机恢复密钥，保存在当前浏览器、当前网站来源的localStorage中。网页刷新和网络重连先验证身份，再获取完整房间快照，恢复棋盘、轮次、结果和当前阶段。

同一浏览器的普通标签共享身份，第二个标签会接管，旧标签停止自动重连和操作。两人测试请使用普通窗口+无痕窗口，或两个不同浏览器；第三名玩家使用第三个独立浏览器环境。localhost与127.0.0.1、5173与3000都属于不同来源，不共享恢复信息。

首局双方准备，A座黑、B座白。结算后双方都点击“再来一局”才开始；原两人交换黑白。有新人替换则视为新组合，A黑B白，不能继承前任的准备或胜负身份。

## 掉线、离开与清理规则

掉线不等于主动离开。playing中任一人掉线暂停双方落子，原座位保留。60秒宽限期从服务端识别掉线开始计算；心跳用于检测没有正常断开通知的连接，识别可能有短暂延迟。

60秒内原玩家可恢复。60秒后不自动释放或判负；在线本局对手可以选择判自己获胜，或继续等待。继续等待不会新增一段禁止判负期限，也不踢人，之后仍可选择判赢。waiting和finished不追溯改写结果，也不自动踢掉保留座位；在线方可离开另建房间。

点击“离开房间”是明确的业务操作：playing中视为认输并释放座位，其他阶段只释放座位。刷新、关标签或网络中断不会发送认输。离开绑定当前roundId，迟到的旧局离开请求不能影响下一局。

M3中胜者在drawing主动离开，会放弃未确认笔画并立即结束画脸；输家离开不改变被冻结的结算目标。空座可加入新人，但新人不能继承前任的输家身份、笔迹或画笔资格。

两个座位含离线保留位都被占用时，第三人只看到房间已满和创建新房间按钮，无法读取任何成员或棋局状态。只有原座位所有者能通过密钥恢复；不是自报playerId就可以。

双方连续不在线10分钟后销毁房间，所有棋局与累计笔迹清除。有效加入/恢复取消清理计时，第三人满房访问不会延长房间寿命。

## 画脸与洗脸规则

核心循环：下棋 → 分出胜负 → 画脸 → 双方准备再来一局。五连、认输与超时判负均奖励本局赢家一次画脸机会，目标始终是本局原输家；平局直接结束，不进入画脸。

画脸开始后有20秒服务端绝对时限。赢家可从六色中选择颜色，在放大脸面板内按下开始、连续拖动、松开结束一笔。鼠标与触摸均吸附到32×32网格、固定一格粗细；每约50ms发一批点，输家实时看服务端已接受的轨迹。赢家即时本地预览不是存档，只有松开、最后批次和整笔均获服务端确认，才保存到输家脸上并进入finished。单点也算一笔；不能画第二笔。

点数和频率受服务端限制：每批最多32点、整笔最多1024个输入点（包括起点）、约25批/秒并容许小幅突发。服务端验证赢家、控制连接、房间/本局/画脸ID、序号、坐标与期限。超过20秒仍未完整确认的草稿全部丢弃；点击跳过也丢弃当前草稿，不清除以前已确认笔迹。

同一房间的确认笔迹按玩家身份跨局累积，黑白交换不交换脸。像素底图存完整累计覆盖层，原始轨迹仅保留最近4条，历史压平不影响视觉。新人脸干净；原身份重新加入尚存的同房间，可恢复本人的累计脸。

waiting/finished且两人在线时可发起“洗脸”。发起者已同意，另一人30秒内点击接受，才一次性清空当前两名玩家的笔迹。拒绝、超时、掉线、成员/阶段/画布变化均取消；一人点击绝不会立即清空。

drawing期间掉线不暂停20秒计时。输家离线仍可被画并保存。赢家原页面如仍保留真实松开和未确认队列，可在身份、完整快照恢复后用剩余时间补交；刷新丢失本地手势队列，不会伪造松开或奖励第二笔。刷新看到已有草稿时可跳过或等到期，不能自动存档。

## M2 人工验收

### 刷新恢复

普通窗口A创建、独立窗口B加入并准备，轮流下几手。在A刷新页面。应自动回到同一房间，昵称、棋子、轮次不变；B短暂等待后恢复对局。无需重新输入昵称、加入或准备。

### 弱网与断线

在B的DevTools → Network选择Slow 3G等弱网条件，确认轮流落子仍保持一致。再选Offline，A应显示“对方掉线，等待重连”，双方不能继续落子。用第三独立身份尝试加入，应仍然满房。

60秒内把B恢复到在线网络。B应自动重连，完整棋盘与轮次恢复后才可操作。仅显示Socket已连接不代表业务恢复完成。

### 超时裁决

另开一局，让B离线并等待A的60秒倒计时结束。座位不能自动释放。A可先选择“继续等待”，房间仍暂停且满房；随后选择判自己获胜，结果确定并空出B座位。第三人此时可加入，B回来不能抢占新人座位。

### 再战与新玩家

完整结束一局，M3先完成或跳过画脸，再只让一方点击再来一局，游戏不能提前开始；另一人也点击后，棋盘清空、roundId更新，原两人黑白交换。另测试playing中一人主动离开并确认认输，对方胜、座位空出；新人加入等待前任画脸完成后双方准备，新组合A黑B白，新人不是上一局输家。

### 同身份双标签

A已在局内时，在A同一浏览器新开普通标签访问房间链接。新标签应恢复原身份与棋局，旧标签显示被接管，不能下棋或离开认输，不循环抢回连接。独立B仍是另一名玩家。

### 服务重启与房间过期

保持浏览器打开，在终端Control+C停止服务再启动。服务端纯内存房间与身份已消失，应明确提示原房间失效，并允许重新建立身份/建房，不应恢复出本地假棋盘。断网连接失败本身不能清除恢复信息。

10分钟清理可由自动化可控时钟快速验证；人工测试则让双方都离开或关闭窗口，连续10分钟无人恢复，再以新身份通过旧房间码加入，应提示房间不存在。

## M3 人工验收

### 实时一笔与保存

普通窗口A创建、独立窗口B加入并准备，让A获胜。双方应看到B的放大像素脸、20秒倒计时和各自胜负，只有A有画笔操作权。A选色按住拖动，先不要松开；B应连续看到轨迹，而累计确认笔迹仍未增加。A松开后双方结束画脸，B的脸留下图案，再来一局按钮出现。

### 累积、洗脸与跳过

双方再战，确认黑白交换，脸上旧笔迹不丢。再让同一身份输，画第二笔后应同时保留旧、新笔迹。A点洗脸时不能立即清空；B先拒绝应保留全部图案，重发后B接受才清空双方。另开一局点击跳过，或画到一半点击跳过，草稿不能残留到下一局。

### 手机触摸

手机与另一设备访问同一局域网Vite地址，或DevTools手机模拟。让手机玩家赢，在放大脸面板触摸拖动并松开，应正常保存，另一设备实时看见笔画。绘画区域不误滚页面，面板外仍可正常滚动。

### 刷新、掉线与20秒

赢家按住绘制时刷新输家窗口，输家应恢复草稿而不是提前保存。再测试刷新赢家：已用的一笔不能重新开始，不会自动结束存档，可跳过。让赢家按住画、DevTools切Offline并等20秒到期，在线输家仍按时结束画脸，未确认笔画全部丢弃。重新上线只恢复权威结果，不补出本地假图案。

### 前任目标和离开

playing时输家主动离开，新玩家进入空座。画脸仍针对原输家，不能画在新玩家脸上；新人等待、不能画或准备。画脸完成后让新人离开，原输家用同一身份重入，应恢复自己的图案。另测试赢家画脸中通过按钮离开：本笔丢弃、既有胜负不改写，不能把输家变成赢家。

## M4 人工验收

### 像素棋友与状态

桌面打开普通窗口A和独立窗口B，创建/加入同一房间。棋盘应在中间，两位完整像素棋友在左右，服装可辨识。准备后轮到谁，谁进入思考；对方确认落子后短暂看向棋盘。分出胜负后，赢家欢呼、输家不服；实际画脸时原输家显示被画表情，画完回到结果表现。重新开始、交换黑白、人物动作都不能清掉脸上的累计笔迹。

### 音效、静音和刷新

首次真实点击、触摸或按键后才解锁声音。双方轮流落子应听到短落子声，轮到自己有提示；本局胜负各自只听一次对应音效；实时画笔有轻声反馈。顶栏静音立即停止声音并保存在当前来源的浏览器存储中。静音后刷新仍静音；取消静音不补播历史声音，只播放之后的实时确认事件。浏览器拒绝音频或不支持Web Audio时不影响下棋和画脸。

### 手机与减少动画

手机端双人小人在棋盘上方，棋盘和画脸面板可操作，无横向溢出；画布外可以正常滚动，触摸拖画不误滚页面。系统或DevTools启用“减少动态效果”时，人物保留可识别表情和状态，但减少跳跃与抖动。

### 掉线、恢复和双标签

playing时一方DevTools切Offline，页面应优先显示离线/等待重连，而不是正常轮次。恢复后完整棋盘和脸回到权威状态，不重放旧落子、胜负或画笔声。同身份新标签接管后旧页提示停止操作，旧页不能继续播后续对局事件。免费部署服务器休眠时初次连接可能等待几十秒；本轮仍是本地版本，不代表已完成Render上线。

## 当前限制与部署状态

M3提供静态像素脸和绘画载体，完整小人动作、动画与音效在M4开发；仍不做悔棋、聊天、排行榜、陌生人匹配、观战、账号或永久作品保存。画脸超时、跳过或未完整确认的草稿不保留。

全部状态在单Node进程内存中，服务重启、重新部署或未来Render休眠后无法找回原房间和身份，不支持水平扩容。浏览器本地凭据被清除后也不能找回原座位。localStorage不可用时应提示降级，刷新恢复将不受保证。

服务级上限500个房间、2,000个身份，普通业务请求每连接10秒最多240次；画笔批次使用专用限频，消息体16KB。未占座身份可按内存压力清理，房间按双方连续离线10分钟清理。

单房间最多保留64名历史身份的脸（含当前玩家），达到上限时不删除旧图案；全新身份需创建新房间，已有身份仍可进入空座并恢复自己的脸。这是纯内存首版的资源保护限制，不影响同两人持续对局和笔迹累积。

Render上线属于M5，目前没有生产线上地址。计划配置为显式Free、单实例、/healthz、process.env.PORT，构建`npm ci && npm run build`，启动`npm start`。完整部署步骤和免费档休眠/唤醒限制见SchemeDesign.md，M5交付实际render.yaml和线上测试结果。
